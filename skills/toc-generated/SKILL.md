# Генерация оглавления для Markdown

Генерирует и поддерживает блок оглавления (TOC) в начале markdown-файла
на основе его заголовков.

## Когда использовать

Use this skill when the user wants to create or update a table of contents
in a `.md` file, for example "сделай оглавление", "обнови содержание",
"добавь TOC", "сгенерируй содержание из заголовков".

## Алгоритм

1. **Определить целевой файл.** Это `.md`-файл, который указал пользователь
   (либо единственный `.md`-файл в контексте). Уточните путь, если неясно.

2. **Прочитать файл** полностью, чтобы получить актуальные заголовки и
   существующий блок оглавления (если он есть).

3. **Собрать заголовки.** Постройте список всех строк, начинающихся с
   `#`, `##`, `###`, `####` и т.д. Игнорируйте:
   - заголовки внутри самого блока оглавления (по маркеру, см. ниже);
   - закомментированные строки;
   - заголовки внутри fenced-блоков кода (строки между ``` ... ```), если
     это меняет смысл, но на практике встречается редко — допускается
     учитывать только строки, начинающиеся с `#` в начале строки.

4. **Сгенерировать ссылки.** Для каждого заголовка создайте строку вида:
   ```markdown
   - [Текст заголовка](#anchor-slug)
   ```
   Уровень вложенности отражается отступами (например, 4 пробела на
   уровень). Текст заголовка — без ведущих `#` и лишних пробелов.
   `anchor-slug` строится по правилам GitHub:
   - приводится к нижнему регистру;
   - пробелы заменяются на `-`;
   - удаляются символы пунктуации, кроме `-` и `_`;
   - если встречаются одинаковые слаги, к последующим добавляется
     суффикс `-1`, `-2`, ... (используйте тот же закон, что и движок,
     для которого пишется документация — по умолчанию GitHub).

5. **Обернуть блок в маркеры.** Оглавление обрамляется чёткими маркерами,
   чтобы его можно было найти и заменить:
   ```markdown
   <!-- TOC:START -->
   ## Оглавление

   - [Заголовок один](#заголовок-один)
     - [Подзаголовок](#подзаголовок)
   <!-- TOC:END -->
   ```

6. **Определить, существует ли уже оглавление.**
   - Ищите блок по маркерам `<!-- TOC:START -->` ... `<!-- TOC:END -->`.
   - Если блок найден — **актуализируйте** его: замените содержимое между
     маркерами на только что сгенерированное, оставив маркеры на месте.
   - Если блока нет — **вставьте** новый TOC-блок (с маркерами) в самое
     начало файла.

## Позиция вставки

- При вставке нового оглавления разместите блок **в самом начале файла**.
- Если файл начинается с YAML-frontmatter (блока между `---` и `---`),
  разместите TOC **после** frontmatter, а не перед ним.
- Не дублируйте блок: один файл — одно оглавление.

## Формат блока

Итоговый блок в файле имеет вид:

```markdown
<!-- TOC:START -->
## Оглавление

- [Раздел](#раздел)
  - [Подраздел](#подраздел)
- [Другой раздел](#другой-раздел)
<!-- TOC:END -->

<остальное содержимое файла>
```

Маркеры `<!-- TOC:START -->` и `<!-- TOC:END -->` обязательны: по ним скил
распознаёт и обновляет существующее оглавление, не создавая дубликат.

## Проверка результата

- После записи прочитайте файл и убедитесь, что блок один.
- Проверьте, что каждой ссылке в TOC соответствует реальный заголовок.
- Убедитесь, что существующее оглавление обновлено, а не продублировано.
